# song_board_model

`src/song_board_model.js` — Phase 2 최애곡 모음 앱의 데이터 규칙. DOM과 무관한 순수 함수다.

- 곡 모양: `{ id: 'song_3', title, artist, is_favorite, memo, link_url }`. 곡과 배열은 동결하고, 바꿀 때는 새 배열과 새 곡을 만든다. 바뀌지 않은 곡은 같은 객체를 공유한다.
- 대상이 없거나 내용이 같으면 **같은 배열**을 돌려준다. `use_state`가 `Object.is`로 비교하므로 State가 그대로라 다시 그리지 않는다.
- 메인곡은 곡 복사본이 아니라 `main_song_id`만 저장한다. 곡을 고치면 메인 카드도 자동으로 같아진다.
- **중복 규칙:** 제목과 가수를 정규화(앞뒤 공백 제거, 연속 공백은 한 칸, NFC)하고 대소문자를 무시해 둘 다 같으면 같은 곡이다.
- **링크:** `http:`, `https:`만 받는다(`new URL`로 해석). `javascript:`, `data:`, 상대 주소는 거부한다.
- **저장:** `serialize_board` / `parse_saved_board`. 저장된 적이 없으면 샘플 곡 3개, 깨진 JSON이면 빈 목록으로 시작한다. 저장된 곡은 입력 폼과 같은 규칙으로 다시 검사해 잘못된 곡만 뺀다.
- **id:** `song_<번호>`. 지금까지 쓴 가장 큰 번호(`last_song_number`, 저장됨) + 1이라 삭제한 번호를 다시 쓰지 않는다. 목록 행의 key로 쓰이므로 재사용하면 삭제한 곡의 DOM이 새 곡에 붙을 수 있다.
