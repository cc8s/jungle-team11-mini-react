# operation_summary

`src/operation_summary.js` — patch 연산을 "N개 변경 반영 (ADD 1, TEXT 2)" 요약과 연산별 설명 문장으로 바꾸고, 화면에 보이지 않는 변경(주석, 공백)을 가려내는 순수 함수.

## 화면 변화 없는 변경 (주석, 공백)

테스트 영역에서 주석 안에 공백이나 이모지를 넣거나, 태그 사이 공백만 바꾸고 Patch하면 실제 영역 DOM은 실제로 바뀐다(주석 노드, 공백 텍스트 노드의 내용이 patch됨). 하지만 주석은 그려지지 않고 태그 사이 공백은 한 칸으로 접혀 그려지므로 화면에는 변화가 없다.

| 처리 | 결정 |
| --- | --- |
| State History | **Patch 기록으로 남긴다.** 새 상태로 저장하고 카드 요약을 `주석 1개 변경 · 화면 변화 없음`, `공백 2개 변경 · 화면 변화 없음`처럼 쓴다. 요약 글자는 한 단계 연한 회색(`history_summary_quiet`) |
| 실제 영역 | **표시하지 않는다.** 하이라이트(회색 상자)를 띄우지 않는다. 띄우면 부모 요소 전체가 깜빡여 오히려 헷갈린다 |
| 보이는 변경과 섞임 | 보이는 변경만 하이라이트하고, 요약은 `2개 변경 반영 (TEXT 1, 주석 1)`처럼 함께 센다 |

판정 규칙 (`find_hidden_change_category`, 레이아웃을 보지 않는 근사 규칙):
- 주석 노드의 `TEXT`, `ADD`, `REMOVE`, `MOVE` → `comment`
- 바뀌기 전후가 모두 접히는 공백(스페이스, 탭, 줄바꿈, 폼피드)만 있는 텍스트 노드 → `whitespace`. nbsp는 화면에 보이므로 제외
- `<pre>`, `<textarea>`, `<listing>`, `<plaintext>` 안의 공백은 그대로 보이므로 제외 (이를 위해 diff의 `TEXT` 연산에 부모 노드를 담음)
- 주석과 공백 노드끼리의 `REPLACE` → 새 노드의 종류
- `ATTRIBUTES`, 요소 노드 변경 → 보이는 변경
