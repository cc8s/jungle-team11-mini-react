# state_history

`src/state_history.js` — Patch로 확정한 Virtual DOM 트리를 "확정 순서"대로 보관하는 이력. DOM과 무관한 순수 함수이며 모든 함수가 새 이력 객체를 돌려준다.

## 이력 규칙 (`plan.md` 2절)

1. 기준은 확정(Patch) 시간순이다.
2. 뒤로/앞으로 이동은 이력 순서를 바꾸지 않고 현재 위치만 바꾼다.
3. Patch할 때 비교 기준은 "지금 보고 있는 상태"다.

| Patch 상황 | 처리 | `outcome` |
| --- | --- | --- |
| 맨 앞에서 변경 없음 (연타 포함) | 저장하지 않음 | `unchanged` |
| 뒤로 간 상태에서 변경 없음 | 그 상태를 맨 앞으로 올림 | `promoted` |
| 이력의 다른 상태와 내용이 같음 | 그 항목을 맨 앞으로 올리고 그 트리를 그림 (같은 상태는 한 번만 보관) | `deduplicated` |
| 새로운 변경 | 맨 앞에 추가 | `appended` |

- 최대 개수(기본 50)를 넘으면 가장 오래된 항목부터 버린다. 초기 상태(v0)도 보호하지 않는다. 오래된 상태보다 최근 작업이 검증에 더 중요하다고 보고 정했다.
- 항목 번호(`entry_id`)는 순서를 바꿔도 유지되므로 화면의 `v0`, `v1` 표시가 바뀌지 않는다.

| EC-007 | 예전 상태와 같은 내용으로 편집 후 Patch | 그 항목을 맨 앞으로, 그 트리를 반환 | EC-007 이력에 이미 있는 내용으로 Patch하면 그 항목을 맨 앞으로 올리고 그 트리를 돌려준다 | 통과 |

| EC-009 | 범위 밖, 소수, `NaN`, 문자열, `null` index | 같은 이력 반환 | EC-009 범위 밖이나 정수가 아닌 index로 이동하면 같은 이력을 돌려준다 | 통과 |
| EC-010 | 이전 이력 객체 수정 시도 | 동결되어 수정 불가, commit 후에도 이전 이력 그대로 | EC-010 이력 객체는 불변이라 commit과 이동 후에도 이전 이력은 그대로다 | 통과 |
| EC-011 | 최대 개수 1 | 최신 하나만 유지 | EC-011 최대 개수 1이면 항상 최신 한 개만 남는다 | 통과 |
