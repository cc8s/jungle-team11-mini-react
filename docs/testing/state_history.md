# state_history

`src/state_history.js` — Patch로 확정한 Virtual DOM 트리를 보관하는 한 줄짜리 이력. DOM과 무관한 순수 함수이며 모든 함수가 새 이력 객체를 돌려준다.

## 이력 규칙: 브라우저 방식 (갈래 버리기)

브라우저 뒤로가기·앞으로가기, 편집기의 실행 취소·다시 실행과 같은 규칙이다.

1. 이력은 한 줄이다.
2. 뒤로/앞으로 이동은 이력을 바꾸지 않고 현재 위치만 바꾼다.
3. Patch할 때 비교 기준은 "지금 보고 있는 상태"다.

```
v1 → v2 → v3          현재 v3
뒤로가기               현재 v2
수정 후 Patch          v1 → v2 → v4   (v3 삭제)
뒤로가기               v4 → v2 → v1
```

| Patch 상황 | 처리 | `outcome` |
| --- | --- | --- |
| 지금 보고 있는 상태와 같음 (위치와 상관없이, 연타 포함) | 아무것도 바꾸지 않음. 뒤쪽 상태도 버리지 않음 | `unchanged` |
| 다름 | 현재 위치 뒤쪽 상태를 모두 버리고 새 상태를 바로 뒤에 붙임 | `appended` |

- 버린 항목은 `discarded_entries`로 돌려준다. 화면은 이 목록으로 카드 정보를 정리한다.
- 상태 번호(`entry_id`)는 계속 늘어나며 버린 번호를 다시 쓰지 않는다.
- 예전 상태와 내용이 같아도 새 상태로 붙인다(중복 제거 없음).
- 최대 개수(기본 50)를 넘으면 가장 오래된 항목부터 버린다. 초기 상태(v0)도 보호하지 않는다. 이렇게 밀려난 항목도 `discarded_entries`에 들어간다.

## 브라우저 방식 뒤로가기: 기본 동작과 엣지 케이스 구분

뒤로가기 후 수정하는 흐름은 **기본 동작**(사용자가 평범하게 하는 핵심 흐름)과 **엣지 케이스**(경계값, 평소와 다른 상태)가 섞여 있다. 둘 다 아래 표의 같은 ID 유닛 테스트로 검증한다. 화면 쪽(카드가 사라지고 버튼이 꺼지는지)은 `docs/testing/app.md` EC-003, EC-016에서 확인한다.

| 상황 | 분류 | 기대 동작 | 관련 ID |
| --- | --- | --- | --- |
| 맨 앞에서 수정 후 Patch | 기본 동작 | 새 상태를 뒤에 붙임, 버리는 상태 없음 | EC-008 (붙이기 경로) |
| 뒤로 → 수정 후 Patch (`v1 → v2 → v3`에서 v2로) | 기본 동작 | v3을 버리고 `v1 → v2 → v4`, 앞으로가기 불가, 뒤로가기는 v2 | EC-005 |
| 뒤로 → 수정 없이 Patch | 엣지 케이스 (버튼이 꺼져 있어 보통은 일어나지 않음) | 아무것도 바꾸지 않고 뒤쪽 상태 유지 | EC-004 |
| 맨 처음(v0)으로 돌아가 수정 | 엣지 케이스 (버릴 상태가 가장 많은 경계) | v0 뒤 모두 버림 | EC-012 |
| 예전 상태와 같은 내용으로 고침 | 엣지 케이스 (중복 제거를 하지 않는 경계) | 새 상태로 붙임 | EC-007 |
| 최대 개수 초과 | 엣지 케이스 (50개 경계) | 가장 오래된 상태부터 버림, `discarded_entries`에 포함 | EC-008, EC-013 |
| 뒤로가기·Patch 연타 | 엣지 케이스 (반복 호출) | 경계에서 멈춤, 이력 불변 | EC-003, EC-006 |
| 맨 처음에서 뒤로가기, 맨 끝에서 앞으로가기 | 엣지 케이스 (경계) | 변화 없음 | EC-002 |
