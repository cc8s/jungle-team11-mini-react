# diff

`src/diff.js` — 두 Virtual DOM 트리를 비교해 patch 연산 목록을 만들고(`diff_trees`), 안 바뀐 하위 트리를 이전 트리와 공유한다(`share_unchanged_nodes`).

## 동작 규칙

- 연산은 DOM 위치가 아니라 **이전 트리의 노드 객체**를 가리킨다. patch는 북마크(WeakMap)로 DOM을 바로 찾는다.
- 연산 종류: `ADD`, `REMOVE`, `REPLACE`, `MOVE`, `TEXT`, `ATTRIBUTES`, 그리고 북마크만 옮기는 `BIND`(변경으로 세지 않음).
- 형제 짝짓기 (`match_children`)
  1. `id`(key)가 있으면 같은 key이면서 같은 종류(태그, 네임스페이스)인 이전 노드와 짝짓는다. 중복 key는 첫 번째만 쓴다.
  2. key가 없으면 먼저 **내용이 완전히 같은** 이전 노드를 순서를 유지하며 찾는다. HTML 들여쓰기 공백 텍스트가 한 칸씩 밀려 `TEXT`와 `MOVE`가 쏟아지는 것을 막기 위해서다.
  3. 남은 key 없는 노드끼리 순서대로 짝짓고, 종류가 다르면 `REPLACE`한다.
- 적용 순서는 부모마다 `REMOVE` → 새 index 오름차순으로 `REPLACE`/`ADD`/`MOVE` → 짝지어진 자식 재귀. `MOVE`는 제거 후 남은 순서를 그대로 흉내 내며 판단하므로 patch가 실제로 옮기는 횟수와 같다.
- `ADD`와 `MOVE`에는 새 순서에서 바로 앞에 오는 형제(`previous_node`, 맨 앞이면 `null`)를 싣는다. index 오름차순으로 적용하므로 앞 형제는 이미 제자리에 있고, patch는 그 형제의 DOM을 북마크로 찾아 바로 뒤에 넣는다. 외부 코드가 부모에 노드를 끼워 넣어도 순서가 밀리지 않게 하기 위해서다 (`patch.md` EC-025 ~ EC-027). `index`는 그대로 함께 싣는다.
- 같은 참조(공유 노드)는 하위 트리 전체가 같으므로 비교를 건너뛴다.
