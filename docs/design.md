# design.md

현재 디자인 규칙이다. 지금 화면(`index.html`, `src/styles.css`, `src/phase1/app.js`, `src/app/app.js`)을 기준으로 정리했다.
UI를 바꿀 때는 이 규칙을 지킨다. 규칙 자체를 바꿔야 하면 확인을 받은 뒤 이 문서도 함께 고친다.

## 1. 원칙

- **미니멀 그레이스케일.** 밝은 회색 배경 위에 흰 면을 올리고, 글자는 회색, 진회색, 검정만 쓴다. 강조색을 따로 두지 않는다.
- **선 대신 면.** 카드, 로그 카드, 아이콘 버튼, 숫자 배지에는 외곽선을 쓰지 않는다. 구분은 배경색 차이(흰색 / 연회색)로 한다.
- **검정은 "현재"와 "주요 동작"에만.** 현재 페이지 숫자 배지, Patch 버튼, 오목의 흑돌만 검정이다.
- **설명 문구를 붙이지 않는다.** 상태는 색과 위치로 보여 준다. "현재", "맨 앞으로 올림" 같은 문구나 피드백 줄을 두지 않는다.
- **요구사항에 있는 것만 둔다.** 다만 아래 두 가지는 동작의 근거를 보여 주는 장치라 예외로 둔다.
  - Phase 1 **Patch 로그**(MutationObserver): 실제 DOM에서 무엇이 바뀌었는지 보여 준다.
  - Phase 2 **통계 패널**(렌더 횟수, patch 수): batching과 고정 핸들러의 효과를 보여 준다.

## 5. 레이아웃

```
┌──────────────────────────────────────────────────────────────┐
│               Phase 1 · Virtual DOM · Diff · Patch              │  상단 바 56px
├────────────┬───────────────────────────────────┬─────────────┤
│ PAGES      │ ┌ 실제 영역 ──┐ ┌ 테스트 영역 ‹ 2/3 › Patch ┐ │ Patch 로그   │
│ ■1 Phase 1 │ │            │ │ textarea                 │ │  □ Patch ... │
│ ▢2 Phase 2 │ │            │ │ 미리보기                 │ │  ▢ 뒤로 ...  │
│            │ └────────────┘ └──────────────────────────┘ │              │
│  248px     │            1 : 1.25                        │   320px      │
└────────────┴───────────────────────────────────┴─────────────┘
```

- 바깥 박스 없이 화면 전체를 쓴다. 영역 경계는 1px `--border_color` 선 하나로만 나눈다.
- **상단 바:** 가운데에 페이지 제목만 둔다. 버튼을 두지 않는다. 제목은 선택한 메뉴의 `data-title`이다.
- **좌측 사이드바:** 첫 줄에 `PAGES`를 둔다. 그 아래에는 페이지 선택만 둔다.
- **Phase 1 본문:** 실제 영역과 테스트 영역을 1 : 1.25로 나란히 둔다. 최대 폭은 1200px이고 가운데 정렬한다. 두 영역의 최소 높이는 480px이다(1080px 이하 360px).
- **테스트 영역 카드 머리:** 제목은 왼쪽, 뒤로·위치·앞으로·Patch는 오른쪽에 두고 양끝 정렬한다. 입력칸 아래에 미리보기를 둔다.
- **우측 Patch 로그:** 제목과 `MutationObserver`를 양끝 정렬하고, 그 아래에 최신 기록이 위로 오도록 카드를 쌓는다.
- **Phase 2 본문:** 오목 카드(차례·돌 개수·초기화 + 판)와 통계 카드를 나란히 두고, 좁으면 아래로 내린다.

## 6. 컴포넌트

### 사이드바 메뉴

| 상태        | 모양                                                     |
| ----------- | -------------------------------------------------------- |
| 기본        | 배경 없음, 연회색 숫자 배지(`--hover_color`) + 회색 글자 |
| 마우스 오버 | 항목 전체에 `--hover_color` 배경                         |
| 현재 페이지 | 겉박스 없음. 검정 숫자 배지 + 흰 숫자, 글자는 검정 600   |

- 아이콘은 그림 대신 숫자(1, 2)를 쓴다.
- 현재 페이지는 `aria-pressed="true"`로 표시하고, 스타일도 이 속성으로 정한다.
- 접힌 레일에서 글자가 숨어도 이름이 남도록 버튼에 `aria-label`을 둔다.

### 카드

- 흰 배경, 모서리 16px, **외곽선 없음**.
- 제목은 16px 중간 회색이고 카드 안 왼쪽 위에 둔다. 보조 설명 문구는 두지 않는다.
- 테스트 영역 입력칸은 `--main_color` 배경이고 외곽선이 없다(투명 1px). 포커스될 때만 검정 1px 테두리가 생긴다.

### 버튼

| 종류             | 모양                                     | 쓰는 곳                      |
| ---------------- | ---------------------------------------- | ---------------------------- |
| `primary_button` | 검정 면, 흰 글자 600                     | Patch                        |
| `ghost_button`   | 흰 면, `--border_color` 1px, 진회색 글자 | 뒤로가기, 앞으로가기, 초기화 |
| `icon_button`    | 면·선 없음, 34×34                        | (사이드바 접기, 예정)        |

- 비활성 상태는 투명도 0.38에 `not-allowed` 커서다.
- 키보드 포커스는 검정 2px 윤곽선을 2px 띄워 그린다.
- 테스트 영역 카드 안쪽 폭이 380px 이하이면 뒤로가기·앞으로가기는 글자를 숨기고 화살표만 보인다. `title`과 `aria-label`은 유지한다.

### Patch 로그 카드

| 상태        | 모양                                 |
| ----------- | ------------------------------------ |
| 기본        | 배경·외곽선 없음                     |
| 마우스 오버 | `--hover_color` 배경                 |
| 최신 기록   | 흰 배경. "최신" 같은 문구는 두지 않음 |
| 비어 있음   | `--faint_gray_color` 1px 점선 상자, 문구 없음 |

- 오류 기록도 강조색을 쓰지 않고 `--ink_color` 글자로 둔다.

### 실제 영역·미리보기 안의 사용자 콘텐츠

- h2는 22px 600이고, 문단은 진회색이며, 목록은 왼쪽으로 20px 들여 쓴다.
- 입력란·버튼·select는 `--border_color` 1px, 모서리 10px이다. 체크박스와 라디오는 `accent-color: --ink_color`다.
- 패널 제목 규칙(`.card_title`)이 사용자 h2를 덮지 않도록 사용자 콘텐츠 규칙은 `.surface` 안에서만 정한다.

### 오목 판

- 판은 `--hover_color` 면이고 격자는 `--faint_gray_color` 0.5px 선이다. 레퍼런스(codingapple1/gibo)의 구조(18×18 선 격자 위에 19×19 교차점 격자를 반 칸 어긋나게 겹침)는 그대로 쓰고, 색만 이 규칙에 맞췄다.
- 흑돌은 `--inverse_color` 면에 흰 수순 번호를 쓴다. 백돌은 흰 면에 `--soft_gray_color` 1px 테두리, 검정 번호를 쓴다.
- 빈 칸에 마우스를 올리면 `rgb(0 0 0 / 0.12)` 원이 나타난다.
- 칸 크기는 `clamp(11px, (컨테이너 폭 - 카드 여백) / 20, 28px)`로 화면 폭에 맞춘다.

## 8. 하지 않는 것

- 카드, 로그 카드, 아이콘 버튼, 숫자 배지에 외곽선을 두지 않는다.
- 페이지 바깥을 감싸는 박스, 둥근 창 테두리, 그림자를 두지 않는다.
- 본문에 큰 안내 문장, 피드백 줄, Virtual DOM 패널을 두지 않는다. Patch 로그와 통계 패널은 1장의 예외다.
- 카드 제목 옆에 보조 설명("diff 결과만 patch" 등)을 두지 않는다.
- 사이드바에 페이지 선택 외의 항목(바로가기, 로고, 안내 카드)을 두지 않는다.
- 노랑, 초록, 파랑 같은 강조색을 쓰지 않는다.

## 9. 다음 단계 (아직 구현하지 않음)

동작이 바뀌는 항목이라 테스트를 먼저 정한 뒤 넣는다.

- **사이드바 접기:** 접기 버튼(`icon_button`)과 `localStorage` 기억, `grid-template-columns` 0.22s 전환. 720px 이하에서는 펼치면 본문 위에 겹쳐 뜨고(그림자 예외 `12px 0 40px rgb(0 0 0 / 0.12)`), 페이지를 고르면 닫힌다.
- **State History 카드 패널:** `v` 배지, `N번째 확정`, 변경 요약, 상대 시간을 둔다. 지금은 테스트 영역 머리의 위치(`2 / 3`)만 보여 준다.
- **상단 바 메타:** `v1 · 상태 3개`.
- **변경 하이라이트:** 바뀐 요소에 `element.animate()`로 연한 회색 상자를 1.4초 동안 띄운다. `class`·`style` attribute는 바꾸지 않는다.
- **단축키:** 테스트 영역에서 `Ctrl`/`⌘` + `Enter`로 Patch한다. 안내는 버튼 `title`로만 한다.
- **Patch 활성 조건:** 테스트 영역을 고쳤거나 이전 상태를 보고 있을 때만 켠다. 지금은 항상 켜져 있고, 바뀐 것이 없으면 로그에 "변경 없음"을 남긴다.
